# Agent roles & approval policy

Agents on this studio site are **policy-bound workflow roles** inside [TUR Company OS](/insights/ai-native-venture-studio-operating-system) — not executives, not autonomous publishers.

Every consequential action — publish, deploy, external send — requires a **human Approve** on the phone. Drafts and research can run under MethodPolicy spend gates; nothing goes live without a gate.

## MethodPolicy roles (not a org chart)

| Role | What it does | Gate |
| --- | --- | --- |
| **Research** | Ingest signals, rank opportunities, draft memos | Level 1–2 — internal only |
| **Draft** | Copy, code and asset drafts under spend caps | Level 1–2 — no external send |
| **Execute** | Bounded commits, builds, internal automation | Level 2 — policy-bound |
| **Publish** | Deploy, IndexNow, outbound | **Level 3+ — human Approve required** |

These map to tooling (OpenRouter, Inngest, Cursor agents) — they are **not** named people or fake leadership.

## Human Approve (always visible)

```
Signal → Decision → Work → Outcome → Lesson
              ↑
        Human gate: Approve · Defer · Reject
        (publish · deploy · external send)
```

- **Approve** — proceed with the proposed external or consequential action
- **Defer** — revisit with a date and reason
- **Reject** — stop; log the lesson

Matches [`/llms.txt`](/llms.txt): agents execute only after human Approve gates.
